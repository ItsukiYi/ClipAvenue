# ClipAvenue技术白皮书
目标：实现从“直播自动录制->存储管理->自动剪辑->自动投稿->自动归档”的全流程自动化。无需过多创造，只需要把现有成熟方案整合起来。

## 1.技术方案
针对直播录制，目前有两种方案：首先是 https://github.com/BililiveRecorder/BililiveRecorder 我们称为mikufans录播姬，优点在于整体设计轻量，稳定性较强，缺点在于仅支持B站直播录制。其次是 https://github.com/biliup/biliup 我们称为biliup，优点在于同时支持B站和抖音的直播录制，且已经实现了将直播录像自动投稿的流程，缺点在于其录制上传流程不够稳定。

针对存储管理，没有太复杂的方案，主要是对过时的录播文件进行自动化删除，以及在存储空间到达阈值前自动清理。

针对自动剪辑，目前测试下来OpenMontage基本可以实现从“录播文件->提取字幕->大模型分析语义->确定剪辑主题->剪辑->字幕压制->切片”的全流程。但存在问题是，仍然需要人工通过与agent对话的形式来完成整个流程。其实在多次完善WORKFLOW之后，整个过程我只需要对agent说“继续”“同意”就行了。

针对自动投稿，目前biliup里面包含的自动投稿命令行工具biliup-rs能够基本实现功能，存在问题在于问题反馈不足，例如投稿失败的处理机制。

针对自动归档，本质就是录播文件备份（上传b站）、流程进展反馈（完成一项发通知）、后处理（已投稿切片多久后删除本地文件等）

## 2.成果要求
以一个集中的GUI进行展现，但整体工作流依赖于命令行代码，GUI只是一个轻量的可视化和常用操作的便捷执行。
dashboard是一个类似于某条地铁上的运行图，将流程节点视为某个占点。例如当前还在直播，那“直播录制”站点就闪烁，假如投稿这里出现问题比如触发风控需要验证码，那“自动投稿”站点就显示红灯说明故障。流程通过“信号”连接，全部完成某一站点的工作才会批准放行进行下一步，每一步也跟地铁一样有预计到达时间。
其他页面就是每个站点的定制化界面，包括比如原始的运行日志，一些开关选项等等。
